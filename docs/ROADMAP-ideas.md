# TenBoost — куда развивать (черновик идей, 09.10.2026)

Сейчас (этап 1): одна встроенная стратегия `preset2_example`, автоподбора нет.
Значит, у части пользователей из коробки не заработает — у разных провайдеров и
регионов нужны разные стратегии. Это главный разрыв между обещанием «одна команда,
и всё работает» и реальностью. Ниже — что это закрывает, по приоритету.

## 1. Автоподбор стратегии (ядро продукта, без него остальное вторично)

СДЕЛАНО (09.10, механизм): кнопка «Подобрать стратегию» в трее → команда `autopick`
службе → служба молча перебирает стратегии каталога (стратегия по умолчанию первой),
на каждой поднимает winws2 и короткими HTTPS-пробами проверяет YouTube (TCP и QUIC) и
Discord, берёт ту, что открыла больше целей, и запоминает. Прогресс в трее «подбор N
из M», значок синий. Если не открылось ничего (провайдер режет не по DPI) — честно
ставит стратегию по умолчанию и пишет об этом. Код: `core/StrategyPicker.cs` (чистый
выбор, под тестами), `service/NetworkProbe.cs` (пробы), перебор в `EngineSupervisor`.

ОСТАЁТСЯ:
- **Каталог пока из одной стратегии.** Перебор работает для любого числа, но выбирать
  не из чего. Нужно наполнить `strategies/catalog.json` несколькими рабочими пресетами
  — только из официальных источников (прогон `blockcheck2` на живом провайдере), не
  выдумывать аргументы: неверные = сломанный обход. Это следующий шаг и его надо
  валидировать на реальной сети, не на машине с туннелем.
- Автозапуск подбора установщиком один раз после установки.
- Кэш результата по «отпечатку сети» (провайдер/ASN), чтобы при смене Wi-Fi не
  перебирать заново.
- Подбор шлёт заметный трафик и перезапускает драйвер на каждой стратегии — при
  большом каталоге продумать тайминги.

## 2. Каталог из нескольких стратегий вместо одной

Собрать 6–10 известных рабочих пресетов (разные провайдеры, разные типы блокировок),
ранжировать от «лёгких» к «тяжёлым». Схема каталога уже позволяет — просто добавить
записи. Автоподбор идёт сверху вниз и берёт первую, что открыла ресурсы.

## 3. Рандомайзер параметров маскировки (твоя идея — да, стоит)

Зачем: если у всех пользователей TenBoost абсолютно одинаковая маскировка, у неё
одинаковая сигнатура, и её можно заблокировать одним правилом разом у всех. Если у
каждой установки параметры чуть разные — блокировать придётся каждого отдельно, что
дорого. Это тот самый приём, о котором говорил IT Jin («разные параметры на разных
серверах»).

Как делать правильно:
- рандомизировать только **косметические** параметры обфускации, которые НЕ влияют на
  то, работает обход или нет (длины, случайный поддельный SNI, мелкие сдвиги). Сами
  рабочие приёмы из подобранной стратегии не трогать — иначе будем ломать то, что
  подобралось.
- сид привязать к установке (один раз сгенерить и хранить), чтобы маскировка была
  стабильной у этого пользователя, но уникальной между пользователями.
- это НЕ замена автоподбору, а добавка поверх выбранной стратегии.

Честная оговорка: эффект против «блокировки пачкой» есть, но переоценивать не стоит —
если провайдер режет по IP или белым спискам, рандомайзер не поможет (это не про DPI).

## 4. Самодиагностика и самолечение

Служба раз в N минут проверяет, открывается ли YouTube. Отвалилось (провайдер сменил
фильтр) → трей краснеет и сам запускает повторный подбор. Пользователь не гадает,
«почему опять не грузится».

## 5. Онлайн-обновление каталога стратегий

Провайдеры меняют фильтры, стратегии протухают за недели. Нужно уметь подтянуть новый
каталог с сервера без переустановки программы. Обязательно: подпись каталога (ed25519),
иначе подменённый каталог = подменённые аргументы winws2. Проверять подпись до загрузки.

## 6. Обновление движка внутри приложения

Вышел новый релиз bol-van → приложение качает новый `winws2.exe` с проверкой SHA256
(механизм уже есть в `build_payload.py`, перенести в рантайм). Без ручной переустановки.

## 7. Что обходить — пресеты + свой список

Переключатели «YouTube / Discord / добавить свой домен». Пользователь дописывает
домены, которые у него не открываются, без правки конфигов.

## 8. Диагностика в один клик для поддержки

Кнопка «Собрать отчёт»: лог службы + what-works снимок + версия движка и стратегии →
один файл, который человек присылает в поддержку. Экономит переписку «а что у вас».

## Недочёты текущего каркаса (кроме отсутствия автоподбора)

- Только TCP/QUIC для YouTube/Discord. Если провайдер режет UDP целиком, QUIC-часть
  молча не работает — нужен фолбэк на TCP и честный статус в трее.
- Нет понятия «сеть сменилась»: подобрал дома, пришёл на работу — не перепроверяет.
- Нет метрики «у скольких сработало» — улучшать каталог вслепую. Анонимная телеметрия
  помогла бы, но это против приватности пользователя: если делать, то строго opt-in и
  без привязки к человеку (иначе противоречит всей затее с анонимностью).
- Антивирус (Defender на тест-машине удалил официальный архив zapret2 как троян) —
  нужен шаг «добавить исключение» в установщике с явным согласием, иначе часть
  установок молча ломается. Это блокер массовости, не мелочь.

## Что НЕ делать

- Не переписывать движок — теряем доверие («свой бинарник = вирус») и поддержку
  апстрима. Остаёмся тонкой оболочкой с проверкой сумм.
- Рандомайзер не должен трогать рабочие приёмы подобранной стратегии.
- Воронку в TENVPN держать мягкой (телефон/нейросети/белые списки → туннель), не
  «вот наш GitHub» — чтобы не связывать инструмент с личностью и сервисом.
